# External CAD evaluation corpus contract

Industrial validation remains uncompleted without suitable legally usable independently annotated CAD. The local audit command prepares supplied evaluation inputs; it does not train a model, report accuracy, establish legal rights or claim manufacturing-feature segmentation.

Use `.venv/bin/python -m backend.dataset_audit /absolute/corpus/dataset.json`. The manifest is strict JSON with schema_version1, a name/source/license/rights_evidence declaration, evaluation_only true, and one to twenty parts. Every part has a contained relative .step/.stp path, exact sha256, a nonempty group identifier and complete original face annotations using face_id0..N-1 and the supported analytic-surface label enum. See backend.dataset_audit.EvaluationDataset for the executable schema. Provenance/rights strings identify supplied evidence, not independently verified permission. Related parts should share a group to support later leakage-safe split planning; this audit does not prove independence from model training.

All bytes are checked before native parsing: manifest64KiB, individual STEP10MiB, aggregate corpus32MiB, no duplicate paths/content, no relative traversal or symlink traversal and only regular files opened nonblocking/no-follow. Missing files fail rather than being downloaded. Per-part geometry parsing reuses the actual bounded disposable worker, so topology/size/face/mesh/resource budgets remain enforced. Parsed face counts must match contiguous annotations; the audit never renumbers IDs or substitutes parsed surface types for supplied ground truth. Raw inputs are retained in memory only up to the bounded corpus budget; each native parse retains its existing thirty-second wall limit, with up to twenty sequential parts.

The output contains manifest/part hashes, group IDs and real parsed face counts, explicitly labeled as an input audit with no performance/legal claim. No CAD corpus is bundled or fabricated for industrial validation. Unit fixtures generate owned procedural solids solely to verify the contract and worker path. Separate held-out evaluation, annotation review, calibration, drift thresholds and publication approval remain required. This trusted local command is not a public dataset-upload endpoint or complete hostile-file sandbox; filesystem-owner races are outside its protections.
