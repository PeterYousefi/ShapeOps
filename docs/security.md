# Threat model and mitigations

Assets: private CAD contents, model artifacts, runtime integrity, telemetry, release state, user machine and eventual cloud account. Trust boundaries: browser → multipart API; raw bytes → native parser subprocess; numerical descriptors → estimator; runtime → local SQLite; CI → eventual deployment credentials.

| Threat | Implemented mitigation | Remaining boundary |
| --- | --- | --- |
| Filename traversal / HTML injection | Fixed temporary internal filename; React escapes display text; raw filenames excluded from logs | No uploaded-file public serving |
| Invalid/malicious STEP | Extension/header checks, OpenCascade solid validation, face/extent/tessellation limits, subprocess timeout, CPU/file caps and Linux address-space/data limits, concurrency bound | Native libraries may contain vulnerabilities; filesystem/network isolation and aggregate resource controls remain required |
| Oversized upload | 10 MB file-read limit plus pre-multipart transport cap (bounded 64 KB envelope); content-length and chunked-body tests | Reverse-proxy request/connection limits still recommended before public exposure |
| Resource exhaustion | 20 inference/drill requests per minute per local client address; four admitted inference/drill requests per process, at most two active CAD processing slots; bounded child runtime/output and native resource ceilings | In-memory rate state is not distributed; aggregate budgets and full worker isolation remain production work |
| Raw-data leakage | TemporaryDirectory cleanup after success/failure/timeout; no contents or filenames in telemetry | Do not enable request-body logging; enforce infrastructure temporary-storage controls |
| Unauthorized production action | Promotion always denied; no cloud credentials; no deployment endpoints | Authenticated OIDC/RBAC implementation required before enabling administrative mutations |
| Unsafe artifact execution | Only internally trained estimators execute; no user model uploads | Never deserialize externally supplied joblib/pickle artifacts |
| Supply-chain compromise | Lockfiles, SHA-256 artifacts, current dependency audits, prepared CI image scan | Image scan and action pinning/security review not complete |
| UI access issues | Keyboard face table and viewport controls, visible focus, modal trap, reduced motion, audited contrast | Automated axe checks do not replace assistive-technology usability testing |

Telemetry retention: retain at most 1,000 request records for seven days and 200 drill records for thirty days, whichever bound removes a record first. Cleanup runs at initialization, on request/drill writes and before telemetry/operations reads, including after idle periods. Indexed timestamp/ID ordering makes count eviction deterministic; cleanup and inserts share a transaction. This limits retained rows, not SQLite file bytes: deleted pages may remain allocated for reuse, and deletion is not secure erasure. No automatic VACUUM or production storage guarantee is claimed. SQLite raw file access is local filesystem access; encryption at rest depends on host storage. The workstation is the developer trust boundary.

Response headers include request IDs, nosniff, same-origin referrer policy and frame denial. TLS is expected from the deployment ingress; no claim of local HTTPS is made. Logs are JSON for inference events but server access/startup logs remain the Uvicorn format. Define a full production log schema before deployment.

## Disposable CAD worker budgets

Before importing CadQuery/OpenCascade, each worker lowers its inherited resource ceilings: 25 CPU seconds, no core dumps, and a 24 MiB per-file limit. Linux additionally applies a 2.5 GiB mapped-address-space ceiling and a 1 GiB data-segment ceiling. Stricter inherited limits are preserved. macOS is not claimed to enforce the Linux memory ceilings. The parent retains the 30-second wall timeout; CPU and wall time are distinct budgets. See the [Python resource API](https://docs.python.org/3.14/library/resource.html) and [subprocess timeout behavior](https://docs.python.org/3.14/library/subprocess.html#subprocess.run).

The worker writes finite JSON into a private temporary result file, using a counted streaming encoder and atomic replacement. Output above 24 MiB is rejected, even when geometry is below the independent face/triangle limits. The parent reads at most 24 MiB plus one byte, requires a regular, non-symlink result (opening nonblocking to reject FIFOs), rejects malformed/non-object results and nonzero worker exits, and discards native stdout/stderr rather than buffering potentially unlimited diagnostics in API memory. Temporary input, partial output and results are removed after success or failure. Worker BLAS/OpenMP thread hints are set to one; those hints are not a substitute for kernel resource limits.

These are resource ceilings, not a complete sandbox. The native worker still runs with the service UID and inherited filesystem/network access. Container aggregate limits, distributed abuse controls, read-only filesystems and stronger process isolation remain prerequisites for hostile public traffic. Unit tests use disposable child processes for CPU/file enforcement; the memory probe runs only on Linux. Genuine STEP round-trips exercise the limits with the actual native dependency stack.

## Request admission

A per-process ASGI gate admits at most four POST requests across sample inference, STEP upload and incident drills. Excess requests receive 503 with Retry-After: 2 before their body is consumed or multipart parsing starts. The gate has no waiting queue; with two active CAD slots, at most two admitted uploads can wait for parsing. Health, registry and other read endpoints remain outside this gate. Slots release on response completion or errors. Cancelled uploads retain their slot and CAD semaphore until the bounded native thread/subprocess finishes, including repeated cancellation. This bounds retained upload bodies; it does not replace ingress slow-client deadlines, distributed rate limiting or aggregate container budgets. The existing per-address 20/minute rate check still occurs inside routes after parsing; pre-body per-address throttling remains open.
