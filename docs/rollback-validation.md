# Isolated revision rollback acceptance

The required Kubernetes CI job now extends the disposable Kind lifecycle beyond restart. After healthy native STEP inference it captures the current Deployment/revision, then sets SHAPEOPS_DATA_DIR to an unwritable /proc path in that cluster only. The new revision must fail its bounded rollout; saved controller/pod state must demonstrate unavailable replicas and actual failed candidate-container execution, not merely a command timeout. A current-context guard requires kind-shapeops before mutation.

kubectl rollout undo targets the captured healthy revision. Rollout readiness must recover, and before/after pod specifications must match exactly, including image, resources, mounts and security controls. Revision numbers must increase through the injected fault and rollback; captured generations must be observed. Restored filesystem probes and actual STEP upload/inference execute again before final evidence validation. No public production deployment, arbitrary image pull, serving-user process or cloud resource is changed. The disposable Recreate workload intentionally has downtime; this is not a zero-downtime/production rollback guarantee or persistent data recovery test.

Raw baseline/fault/restored Deployment snapshots, failed pod state and rollback-evidence.json upload as kind-rollback-evidence, including on failed jobs when available. Pure synthetic negative tests verify the validator rejects healthy faults, absent crashes, changed images/specifications, stale generations and missing recovery. Actual execution requires hosted Docker/Kind; local workstation lacks them. No runtime acceptance is claimed from unit fixtures. Administrative authorization, Azure revision traffic controls and durable release history remain unfinished.

References: [Kubernetes deployment rollback](https://kubernetes.io/docs/concepts/workloads/controllers/deployment/#rolling-back-a-deployment) and [kubectl rollout undo](https://kubernetes.io/docs/reference/kubectl/generated/kubectl_rollout/kubectl_rollout_undo/). Actual captured runtime state remains the compatibility proof.
