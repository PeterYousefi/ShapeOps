# Terraform static security gate

The required terraform CI job now runs Trivy 0.76.0 misconfiguration analysis after fmt/init-backend=false/validate. The installer downloads only the owning repository's release archive, verifies a committed SHA-256 and installs into a temporary tool directory. It supports the verified macOS ARM64 and Linux x86-64 archives. Checksums come from the [official release](https://github.com/aquasecurity/trivy/releases/tag/v0.76.0); signature/maintainer-identity verification is not claimed.

The scanner uses a fresh cache with skip-check-update, selecting checks embedded in the pinned binary rather than a mutable policy download. Trivy logs an error-level fallback message when the cache is absent; actual scan execution is independently required by report validation and a positive control. See [official scanner documentation](https://github.com/aquasecurity/trivy/blob/v0.76.0/docs/guide/scanner/misconfiguration/index.md). HIGH/CRITICAL findings fail CI with no ignore files or suppressed rule IDs. Empty reports, no Terraform coverage and missing check counts fail closed. A deliberately insecure fixture under tests/fixtures/insecure-terraform must produce real high/critical findings and a nonzero scanner exit before the project scan can pass. The fixture is never provisioned and its report is explicitly named positive-control.

Both JSON reports upload as terraform-security-evidence even on failure. Raw local reports are ignored; artifacts/terraform-security-validation.json records the actual local comparison. Original Terraform had one critical storage default-allow rule. The project now explicitly denies unmatched storage network access, disables public storage networking and permits authenticated trusted Azure services as required by the embedded policy. No resources were changed: this is undeployed configuration. A private endpoint/VNet/access-path design must be approved and validated before cloud storage can be used by the app; that network integration is not implemented by this change.

Lower-severity findings remain: storage logging, infrastructure encryption and geo-redundancy. LRS remains the bounded original design; any availability/cost tradeoff requires the future costed deployment review. No findings were waived. Static scanning with unresolved subscription/image/storage-name inputs is not a Terraform plan, cloud runtime audit or deployment approval. No Azure login, provider registration, plan, apply or billable resources are involved. Runtime dependency/image scans and full native-worker isolation remain separate requirements.
