# Application container filesystem boundary

The supplied ShapeOps Compose service and Helm deployment use a read-only application root. Runtime state (SQLite telemetry/journal, immutable model packages and container evaluation reports) writes under `/app/.runtime`; native parser inputs/results and library caches write under `/tmp`. Image code/dependencies remain readable/executable but cannot be modified through those deployment profiles. A bare Docker invocation must explicitly request the same read-only root and mounts; a Dockerfile cannot enforce runtime mount flags by itself.

Container `SHAPEOPS_REPORT_DIR` defaults to `/app/.runtime/reports`, avoiding startup writes to the image's artifacts directory. Developer/CI runs without that variable retain the existing repository artifacts destination. The test API uses its own explicit temporary report directory and verifies the actual trained registry/report contents match. Override both data/report paths only when supplying corresponding writable mounts.

Helm retains UID 10001, capability drop and no privilege escalation, adds the runtime's default seccomp profile, and disables service-account-token mounting because the application has no Kubernetes API role. Kind smoke checks the actual UID, zero effective capabilities, NoNewPrivs and active seccomp, absence of a service token, EROFS when writing the otherwise user-owned image artifacts directory, and successful writes to runtime/tmp. It also reads the actual two-model evaluation report and parses genuine uploaded STEP before and after restart. These runtime assertions must pass in hosted CI; local Helm rendering alone is not evidence of enforcement. Container CI validates Compose syntax before build/security scanning.

This limits filesystem writes; it does not isolate the CAD child from readable application data, writable runtime state or network access. Kernel/runtime-default seccomp is not a CAD-specific syscall profile. Per-worker filesystem/network isolation, aggregate resource sizing and durable cloud storage remain open. Helm uses ephemeral emptyDir runtime storage; Compose uses its named local volume. Do not treat a pod restart as durable registry backup. No Azure deployment or production promotion is enabled.

References: [Kubernetes security contexts](https://kubernetes.io/docs/tasks/configure-pod-container/security-context/) and [Compose read_only](https://docs.docker.com/reference/compose-file/services/#read_only).
